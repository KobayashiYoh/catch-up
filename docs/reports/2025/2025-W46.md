## キャッチアップ（モバイルアプリ開発）

- Flutter3.38.0リリースノート
  - https://blog.flutter.dev/whats-new-in-flutter-3-38-3f7b258f7228
  - Dartのドットショートハンド（Dart 3.10）
    - `MainAxisAlignment.start`を`.start`と書けるように
  - Web設定ファイルのサポート（`web_dev_config.yaml`）
    - host, port, certificate, header, proxyを設定できるファイル
    - React, Vueなどでは以前から使用可能だった
  - `-d web-server` でもステートフルホットリロードが有効化
    - `-d chrome`: Chromeを自動で開く際に利用するターゲットデバイス指定
    - `-d web-server`: Webサーバーだけ起動して自身で任意のブラウザを開く際に利用するターゲットデバイス指定
  - Androidにてpredictive back（戻る予測アニメーション）がデフォルトで有効化
    - https://developer.android.com/guide/navigation/custom-back/predictive-back-gesture?hl=ja
  - Windowsで接続ディスプレイの詳細情報（解像度・リフレッシュレート等）を取得可能に
  - `Badge.count` に `maxCount` パラメータ追加（例：100件 → "99+"と表示）
    - https://api.flutter.dev/flutter/material/Badge-class.html
  - `InkWell` に `onLongPressUp` コールバック追加
  - `SliverGrid.list` コンストラクタ追加
    - SliverGridはGridViewをより高度にカスタマイズできるウィジェット
    - 実は、`GridView`は`CustomScrollView + SliverGrid`の組み合わせで実現されている
    - 従来は、`SliverGrid`に`SliverChildListDelegate`を介してchildrenを渡す必要があった
    - `SliverGrid.list`を用いることにより、childrenを直接渡せるようになった
  - `SliverSemantics` ウィジェット追加（CustomScrollView内のセマンティクス注釈）
  - iOS 26・Xcode 26・macOS 26の完全サポート
  - iOSデプロイに`devicectl`を採用（Xcodeアプリの自動起動が不要に）
    - ctlはcontrolの略で、launchctlやsystemctlなどコマンドラインツールによく使われるサフィックス
    - `devicectl`は、iOSデバイスへのアプリのインストールや起動をコマンドラインから行うツール
  - UIScene Lifecycleへの移行が必須（将来のiOSリリースに向けた対応）
    - 1アプリ=1画面ではなく、1アプリ=複数画面の概念に移行（例：iPadのマルチウィンドウ）
    - 次回リリース（iOS27）までに移行が必要
  - Android 16KBページサイズ対応（2025/11/1よりAndroid 15以上でGoogle Play必須要件）
    - 4KB->16KBへ移行
    - NDKをr28に更新するだけでOK
  - Android NDK r28にデフォルト更新
    - Flutter SDKをアップグレードするだけで良い
  - Androidのメモリリーク修正（3.29.0で混入したバグ）
  - compileSdkVersion / targetSdkVersion が API 36に
  - KGP 2.2.20 / AGP 8.11.1 / Gradle 8.14 の組み合わせを検証済みとして確認
  - Widget PreviewsがIDEに統合（VSCode・IntelliJ/Android Studio）
  - Widget Previewsでライト/ダークモード・カスタムカラースキームをサポート
  - `Preview`アノテーションが継承可能に、`MultiPreview`ベースクラス・`group`パラメータ追加
  - `SnackBar`（アクション付き）が自動非表示しなくなった（Breaking change）
  - `AssetManifest.json` がデフォルトで生成されなくなった（Breaking change）
    - `AssetManifest.json`はassets一覧を保持するファイル
    - 以前は`package.json`に記載したassetsを元に内部で`AssetManifest.json`が生成されていた
    - 代替手段として、`AssetManifest.loadFromAssetBundle()`がある
