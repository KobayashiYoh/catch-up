# 2026-W19週次レポート（05/04〜05/10）

## キャッチアップ（AI）

2.1.128
2026年5月5日

- 引数なしの`/color`がランダムなセッションカラーを選ぶようになった
- `/mcp`が接続済みサーバーのツール数を表示し、0ツールで接続したサーバーにフラグを立てるようになった
- `--plugin-dir`がディレクトリに加えて`.zip`のプラグインアーカイブを受け付けるようになった
- `--channels`がコンソール（APIキー）認証でも動作するようになった。管理設定を持つコンソール組織では、有効化に`channelsEnabled: true`の設定が必要
- `/model`ピッカーを更新。重複していたOpus 4.7のエントリを統合し、現行のOpusは「Opus 4.7」ではなく「Opus」と表示するようになった
- サブプロセス（Bash、フック、MCP、LSP）が`OTEL_*`環境変数を継承しなくなった。Bashツール経由で実行するOTEL計装済みアプリが、CLI自身のOTLPエンドポイントを拾わなくなる
- MCP: `workspace`が予約サーバー名になった。同名の既存サーバーは警告付きでスキップされる
- 再接続するMCPサーバーが、再接続のたびに全ツール名のリストで会話を埋め尽くさなくなった。再アナウンスされたツールはサーバープレフィックスごとに要約表示される
- SDKホストがBashの権限プロンプトに対して永続的な`localSettings`の提案を受け取るようになった。「Always allow」が`.claude/settings.local.json`に書き込まれる
- `EnterWorktree`がドキュメント通りローカルHEADから新しいブランチを作成するようになった（従来は`origin/<default-branch>`）。pushしていないコミットが失われなくなった
- autoモード: 分類器がアクションを評価できない場合、エラーにヒント（リトライ、`/compact`、`--debug`付きでの実行）を含めるようになった
- ヘッドレスの`--output-format stream-json`: `init.plugin_errors`が依存関係のデモートに加えて`--plugin-dir`の読み込み失敗も含むようになった

2.1.129
2026年5月6日

- `--plugin-url <url>`フラグを追加。URLからプラグインの`.zip`アーカイブを取得して現在のセッションで使う
- `CLAUDE_CODE_FORCE_SYNC_OUTPUT=1`環境変数を追加。自動検出が漏れるターミナル（Emacsの`eat`など）で同期出力を強制的に有効化する
- `CLAUDE_CODE_PACKAGE_MANAGER_AUTO_UPDATE`を追加。HomebrewまたはWinGetでのインストールで設定すると、Claude Codeがバックグラウンドでアップグレードコマンドを実行し、再起動を促す
- プラグインマニフェスト: `themes`と`monitors`は`"experimental": { ... }`配下での宣言が推奨になった。トップレベルでの宣言も引き続き機能するが`claude plugin validate`が警告を出す
- `/model`ピッカー向けのゲートウェイ`/v1/models`ディスカバリが、`CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY=1`によるオプトインになった（2.1.126〜2.1.128では自動だった）
- `Ctrl+R`の履歴ピッカーが、デフォルトで全プロジェクトの全プロンプトを検索するようになった（2.1.124以前の挙動に戻した）。`Ctrl+S`で現在のプロジェクトまたはセッションに絞り込む
- サードパーティのデプロイ（Bedrock、Vertex、Foundry、`ANTHROPIC_BASE_URL`ゲートウェイ）で、Anthropicの一次プロダクトを指すスピナーTipsが表示されなくなった
- `skillOverrides`設定が機能するようになった。`off`はモデルと`/`の双方から非表示、`user-invocable-only`はモデルからのみ非表示、`name-only`はdescriptionを折りたたむ
- `claude_code.pull_request.count`のOTelメトリクスが、シェルコマンド経由だけでなくMCPツール経由で作成されたPR／MRもカウントするようになった
- ポリシー拒否のエラーメッセージにAPI Request IDを含め、サポートでのデバッグを容易にした

2.1.133
2026年5月8日

- `worktree.baseRef`設定（`fresh`／`head`）を追加。`--worktree`、`EnterWorktree`、エージェント分離用のworktreeを`origin/<default>`から分岐させるか、ローカルの`HEAD`から分岐させるかを選択できる
- デフォルトの`fresh`により`EnterWorktree`のベースが`origin/<default>`に戻る（2.1.128以降はローカルの`HEAD`だった）
- pushしていないコミットを新しいworktreeに持ち込みたい場合は`worktree.baseRef: "head"`を設定する
- `sandbox.bwrapPath`と`sandbox.socatPath`の管理設定を追加（Linux／WSL）。bubblewrapとsocatのカスタムバイナリ位置を指定できる
- `parentSettingsBehavior`のadminティアキー（`'first-wins'`／`'merge'`）を追加。管理者がSDKの`managedSettings`（親ティア）をポリシーマージに参加させられる
- フックが`effort.level`のJSON入力フィールドと`$CLAUDE_EFFORT`環境変数で、現在のeffortレベルを受け取れるようになった。Bashツールのコマンドからも`$CLAUDE_EFFORT`を読める
- focusモードの挙動を改善
- メモリ逼迫時にウォームスペアのバックグラウンドワーカーを解放し、メモリ使用量を改善
- `claude --help`が`--remote-control-session-name-prefix`と並べて`--remote-control`を表示するようになった

## 学んだこと

- 0ツールのサーバーとは、利用できるツールが1つもない状況のこと
- プラグインアーカイブとは、プラグインに必要なファイルをひとまとめにした配布用ファイル
- `--plugin-dir`が`.zip`のプラグインアーカイブを受け付けるようになったことで、ちょっと動作を試したい使うか使わないかわからないプラグインをあらかじめ展開・配置する必要がないので気軽にプラグインを試せるようになる
- チャンネル機能とは、外部のプログラムやサービスから実行中のClaude Codeセッションにメッセージを届ける仕組み
- Emacsとは、エディタの一種
- eat（Emulate A Terminal）とは、Emacs内でシェルやターミナルアプリを動かすパッケージ
- TODO: `CLAUDE_CODE_PACKAGE_MANAGER_AUTO_UPDATE`を設定しておく
- 自動で呼び出して欲しくないスキルには、`skillOverrides`設定の`user-invocable-only`が有効
- スキル名をClaudeに認識させつつ、説明文によるコンテキスト消費を抑えたい場合は、`skillOverrides`設定の`name-only`が有効
- bubblewrap（bwrap）とは、Linuxでプロセスを隔離し、アクセスできるファイルやリソースなどを制限するためのツール
- socatとは、ネットワーク接続や入出力を中継するためのツール。サンドボックス環境のネットワーク関連処理などで使われる
- `parentSettingsBehavior`とは、SDKホストがClaude Codeに渡す管理者管理の設定
- `parentSettingsBehavior`の`first-wins`は優先度順、`merge`は複数の設定を統合する
- `settings.autoMode`は、通常の`permissions`とは違い、Auto modeの分類器に関するルールを定義する
- `settings.autoMode`には、`hard_deny`の他に、`environment`や`soft_deny`、`allow`もある
- `settings.autoMode.hard_deny`により、なんとAuto mode分類器による不用意なブロックを防ぐことができるのだ
